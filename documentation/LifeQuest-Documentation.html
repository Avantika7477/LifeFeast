1. What is LifeQuest? (Non-technical overview)

LifeQuest turns your daily life into a game. Instead of only writing a to-do list, you track habits, earn points (XP), level up, unlock badges, finish daily missions, and compete on a leaderboard — like a role-playing game for real habits.

Real lifeIn LifeQuest
Good habits (exercise, study, read)Habits you create and mark complete
Getting better over timeXP (experience points) and levels
Rewards for consistencyCoins and badges
Daily goalsMissions
Comparing with friendsLeaderboard
To-do listTasks (daily / weekly / monthly)
Diary + how you feelJournal with mood tracker
Reminders and achievementsNotifications
Simple user journey:
Sign up → Create habits → Mark them done each day → Earn XP → Level up → Unlock badges → Complete missions → Climb the leaderboard.

Three main parts

  1. Frontend (client) — the website you see in the browser (usually port 5173).
  2. Backend (server) — the “brain” that checks login, saves data, awards XP (port 5000).
  3. Database (MongoDB) — permanent storage for users, habits, tasks, journals, etc.

2. How to explain this project (presentation script)

Use this when presenting to teachers, interviewers, or non-tech audiences:

“LifeQuest is a full-stack gamified habit tracker. Users track habits, complete daily missions, and earn XP, coins, and badges — like an RPG for real life.

The frontend is React with Vite: pages for dashboard, habits, calendar, analytics, tasks, journal, notifications, settings, and an admin panel.

The backend is Express with MongoDB: JWT login, REST APIs for every feature, and gamification logic for streaks, levels, and badges.

When you complete a habit, the server updates the database, awards XP, may level you up, updates your streak, and can unlock achievements.”

One-sentence pitch

LifeQuest makes building good habits fun by turning progress into levels, rewards, and friendly competition.

Request example (plain English)

  1. User clicks “Complete habit” on the Habits page.
  2. Frontend calls POST /api/habits/:id/complete with the login token.
  3. protect middleware verifies the token and loads the user.
  4. completeHabit controller updates the habit, XP, streak, progress, badges.
  5. Server returns new stats; UI shows XP / level-up overlay.

7.7 server/models/Habit.js

  • Belongs to a user (foreign key).
  • category: Health, Fitness, Study, Coding, Finance, Meditation, Reading, Business, Personal.

  • target: times per day; completions: list of YYYY-MM-DD dates done.
  • Tracks currentStreak, longestStreak, totalCompletions.
  • getXpReward() returns XP based on difficulty.

7.12 habitController completeHabit (core game loop)

  1. Find the habit belonging to the user.
  2. If already completed today → uncomplete (remove XP/streak effects).
  3. Else add today’s completion, increase totals, call updateUserStreak.
  4. Award XP via user.addXp; may level up and grant coins.
  5. Update daily Progress snapshot.
  6. Run checkAndUnlockBadges.
  7. Return habit + rewards so UI can celebrate.

9. Gamification rules

XP by difficulty

DifficultyXP
Easy10
Medium20
Hard40

Levels

XP needed for level L uses roughly: floor(100 × L^1.5) (cumulative threshold). Crossing a new level grants +50 coins.

Streaks

  • Complete something on consecutive calendar days → streak grows.
  • Miss a day → streak resets to 1 on next activity.
  • Longest streak is remembered separately.

Badges (examples)

BadgeUnlock idea
7 / 30 / 100 Day StreakMaintain streak milestones
Early BirdComplete a habit before 8 AM
Book Worm / Gym Hero / Coding Master / Meditation Monk10+ completions in that category

11. Database models summary

User ──< Habit
  │
  ├──< Task
  ├──< Journal (unique per date)
  ├──< Mission (unique per date+title)
  ├──< Notification
  ├──< Progress (unique per date)
  └──  friends[] → other Users

All user-owned documents store user: ObjectId so one person cannot edit another person’s data.
